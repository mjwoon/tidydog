## 테이블 목록

### `files`

파일 스캔 결과. Phase 1에서 upsert, Phase 3에서 AI 컬럼 추가.

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | INTEGER PK | rowid alias |
| content_hash | TEXT | BLAKE3 hex |
| current_path | TEXT UNIQUE | 현재 절대 경로 |
| size | INTEGER | 바이트 |
| mtime | INTEGER | unix seconds |
| mime | TEXT | MIME 추정 |
| ext | TEXT | 확장자(점 없이) |
| read_level | TEXT | `'content'` 또는 `'metadata'` |
| summary | TEXT | AI 요약(1-2문장). `index_file_content` 성공 시 채워짐 |
| topic_tags | TEXT | JSON 배열 문자열(예: `["세금","의료"]`). 동일 시점 |
| language | TEXT | BCP-47(예: `"ko"`, `"en"`). 동일 시점 |
| proposed_dest | TEXT | `derive_proposed_dest` 성공 시 채워짐 |
| indexed_at | INTEGER | content 인덱싱 완료 unix seconds |
| cluster_id | INTEGER | (미사용) |
| dup_group | TEXT | (미사용) |
| risk_score | REAL | (미사용) |
| last_action | TEXT | (미사용) |
| last_seen | INTEGER | (미사용) |

**P3 컬럼 채워지는 시점**:
1. `index_file_content(path, root)` 호출 →  
   - 동의 확인(N1 gate) → 사이드카로 content 읽기 → CloudSummarizer 호출  
   - `summary`, `topic_tags`, `language`, `read_level='content'`, `indexed_at` 업데이트  
2. `derive_proposed_dest(path, tags, language)` 호출 →  
   - ORGANIZER.md 규칙 평가 → `proposed_dest` 업데이트  

사이드카 에러(깨진 PDF 등) 시 `read_level`은 `'metadata'`로 유지됨.

### `plans`

propose된 실행 계획.

| 컬럼 | 타입 | 설명 |
|------|------|------|
| plan_id | TEXT PK | `plan-<nanos>-<seq>` 형태 |
| created_at | INTEGER | unix seconds |
| status | TEXT | `proposed` / `confirmed` / `executed` / `undone` / `expired` |
| risk_score | REAL | 0.0 ~ 1.0 |
| preview | TEXT | `auto` / `standard` / `full_review` |
| scheme | TEXT | 분류 체계 이름(선택) |
| rule_summary | TEXT | 규칙 요약(선택) |
| ops_json | TEXT NOT NULL | **기존 호환용** JSON 블롭. `plan_ops` 테이블과 dual-write. |

**ops_json vs plan_ops**:  
- `save_plan()` 은 `plans.ops_json` **AND** `plan_ops` 테이블에 동시 기록.  
- `get_plan()` 은 `plan_ops` 우선 읽기, 행이 없으면 `ops_json` 역직렬화 fallback.  
- Phase 3 이전에 생성된 플랜은 `plan_ops` 행이 없으므로 fallback 경로로 읽힌다.

### `plan_ops`  *(Phase 3, T1)*

`plans.ops_json` 블롭의 정규화 테이블. 감사·쿼리 무결성 용도.

| 컬럼 | 타입 | 설명 |
|------|------|------|
| op_id | TEXT PK | `{plan_id}-{seq}` |
| plan_id | TEXT | `plans.plan_id` 참조 |
| seq | INTEGER | 실행 순서(0-indexed) |
| action | TEXT | `move` / `stage` / `rename` |
| content_hash | TEXT | BLAKE3 hex |
| from_path | TEXT | 출발 경로 |
| to_path | TEXT | 목적지 경로 |
| conflict | TEXT | `none` / `rename` |
| reason | TEXT | AI가 제안한 이유(선택) |

인덱스: `idx_plan_ops_plan ON plan_ops(plan_id, seq)`.

### `journal`

실행 이력. append-only (논리적 불변). undo·감사·crash recovery 용도.

| 컬럼 | 타입 | 설명 |
|------|------|------|
| entry_id | INTEGER PK AUTOINCREMENT | |
| plan_id | TEXT | |
| op_id | TEXT | |
| action | TEXT | `move` / `stage` / `rename` |
| content_hash | TEXT | |
| from_path | TEXT | |
| to_path | TEXT | stage op의 경우 `update_journal_to`로 staged_path로 갱신됨 |
| executed_at | INTEGER | intent 기록 시각 |
| **completed_at** | INTEGER **NULL** | **파일 작업 완료 확인 시각. NULL = in-flight** |
| undoable | INTEGER | 1=되돌리기 가능 |
| undone_at | INTEGER | undo 완료 시각(NULL = 미undo) |

**`completed_at` 의미**:
- `append_journal()` 직후에는 `NULL` (intent only, S2 journal-first).
- 파일 작업 성공 후 `complete_journal(entry_id, ts)` 호출로 채워짐.
- `NULL` 항목 = in-flight: 크래시 복원(`recover_inflight`) 대상.
- undo는 `completed_at IS NOT NULL` 항목만 역실행 (미완료 op 건너뜀).

**인덱스**: `idx_journal_inflight ON journal(completed_at) WHERE completed_at IS NULL`.

### `staging`

격리된 파일 추적 테이블. **OS 휴지통이 아닌 앱 관리 디렉터리** 사용.

| 컬럼 | 타입 | 설명 |
|------|------|------|
| content_hash | TEXT PK | |
| original_path | TEXT | 원본 경로(복원 목적지) |
| staged_path | TEXT | `app_data_dir/staging/{content_hash}` |
| staged_at | INTEGER | |
| purge_after | INTEGER | 영구삭제 유예 시각(현재 미사용) |

**staging 경로**: `app_data_dir/staging/{content_hash}`.  
충돌 시 `{content_hash}_{timestamp}` 형태.  
`FsFileOps.restore_file()`은 staging 디렉터리에서 prefix 탐색 후 원위치 복원.

macOS `trash` 크레이트의 `os_limited::restore_all`이 macOS에서 미지원(`#[cfg(not(target_os="macos"))]`)이므로 커스텀 staging 디렉터리로 대체.

## 의미 기반 파일 분류: ORGANIZER.md

파일 위치: 프로젝트 루트 `ORGANIZER.md` (사용자 편집 가능).  
`derive_proposed_dest` Tauri 커맨드가 런타임에 읽어 평가.

### 규칙 형식

```
# 주석
<조건들> -> <목적지 경로>
```

- 조건 키 타입: `tag:`, `lang:`, `ext:`, `name:`
- 같은 줄 조건 = AND
- 키 안의 콤마 = OR (예: `tag:세금,tax` → "세금" OR "tax")
- 평가 순서: 위에서 아래, 첫 매치

### 기본 규칙 (2026-06-29 기준, 14개)

| 조건 | 목적지 |
|------|--------|
| `tag:세금,tax` | `문서/행정/세금` |
| `tag:의료,건강,health` | `문서/의료` |
| `tag:영수증,receipt,invoice` | `문서/영수증` |
| `name:영수증,receipt` | `문서/영수증` |
| `tag:계약,contract` | `문서/계약` |
| `tag:여행,travel,여권,passport` | `문서/여행` |
| `tag:교육,학습,study,school` | `문서/교육` |
| `tag:업무,work,직장,회사` | `문서/업무` |
| `ext:pdf lang:ko` | `문서/PDF` |
| `ext:txt,md lang:ko` | `문서/텍스트` |
| `ext:jpg,jpeg,png,heic` | `사진` |
| `lang:ko` | `문서/기타` |
| `ext:pdf lang:en` | `Documents/PDF` |
| `ext:txt,md lang:en` | `Documents/Text` |
| `lang:en` | `Documents/Misc` |
