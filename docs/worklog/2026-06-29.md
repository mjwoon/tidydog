# 2026-06-29 작업 로그

## 요약

Phase 2에서 안전 코어(tidydog-core)를 외부 의존성 0의 순수 Rust 라이브러리로 완성하고, 단일 트랜잭션 경계 결함(journal-first 무효화)·macOS trash 복원 미지원·inflight undo "source missing" 버그를 발견·수정하며 29개 테스트로 고정했다. Phase 3에서는 Python 사이드카(C-A 프로토콜) → Rust SidecarReader 어댑터 → CloudSummarizer(Claude API + OS 키체인 + 동의 게이트 + 캐시) → ORGANIZER.md 규칙 파서 + 위키 렌더러를 차례로 구현해 총 49개 테스트를 확보했다. 사용자가 요청한 안전선 점검에서 N1 동의 게이트 위치 결함(파일 읽은 후에야 체크)을 발견해 수정했고, 코드를 앞서간 데이터모델·안전명세 문서를 역반영(T2)하고 ADR 5개를 작성했다.

#### 핵심 설계 선택

- **외부 의존성 0 코어**: `crates/tidydog-core/Cargo.toml`의 `[dependencies]`가 비어 있다. `tauri`, `rusqlite`, `reqwest` import는 컴파일 오류다. "위험 능력을 구조로 제거".
- **트레이트 어댑터 분리**: `tidydog-core`는 트레이트(`Store`, `FileOps`, `Guard`)만 정의하고, 구현체(`SqliteStore`, `FsFileOps`, `AppGuard`)는 모두 `src-tauri`에 둬 단방향 의존성 유지.
- **`testing` 모듈**: `FakeStore`, `FakeFileOps` — 실 FS/DB 없이 게이트 전체를 테스트. 15개 gate 테스트가 tmpdir 없이 실행됨.

#### 발견한 결함과 수정

**① 단일 트랜잭션 → op단위 autocommit**

- **발견 경위**: "중간 실패 시 journal에 이동한 파일의 기록이 사라져 undo 경로가 없어진다"는 검토에서 발견. `execute` 전체를 `unchecked_transaction`으로 감쌌을 때 FS 작업은 트랜잭션 밖이므로 파일은 이동됐는데 journal은 ROLLBACK.
- **수정**: execute 루프에서 트랜잭션 래퍼 제거. 각 op를 `[append_journal(completed_at=None) → 파일작업 → complete_journal(entry_id, ts)]` 세 단계 autocommit으로 교체. `GateError::PartialExecute { completed, failed_op_id }` 추가.
- **검증 테스트**: `partial_execute_prior_ops_remain_in_journal`, `partial_execute_then_undo_reverts_completed_ops`, `journal_first_completed_at_set_after_execute`

**② macOS trash 복원 미지원 → staging 디렉터리**

- **발견 경위**: `trash` 크레이트 소스 확인 결과 `restore_all`이 `#[cfg(not(target_os = "macos"))]` 조건부 컴파일. macOS에서 존재하지 않음. undo가 `Action::Stage`를 역실행할 수 없음.
- **수정**: `Action::Stage` 목적지를 `app_data_dir/staging/{content_hash}`로 변경. `staging` DB 테이블로 매핑 추적. `restore_file`은 exact match → prefix 탐색 순.
- **검증 테스트**: `stage_and_restore_roundtrip` (fileops_integration), `stage_is_soft_delete_and_restorable` (gate)

**③ inflight undo "source missing" 버그**

- **발견 경위**: crash 후 `completed_at=NULL` 항목을 undo 시 파일이 이미 원위치에 있는 경우(`from` 경로에 파일이 없는 경우) panic.
- **수정**: `recover_inflight()`에서 `from_path.exists()` 확인: 없으면 "이미 되돌아간 것"으로 간주 journal을 completed로 mark. `to_path.exists()` 확인: 있으면 다시 staging으로.
- **검증 테스트**: `recover_inflight_from_exists_means_op_not_started`, `recover_inflight_to_exists_marks_completed`

### Phase 3 — AI 콘텐츠 파이프라인

#### Pre-subagent — 공유 계약 + T1 + T2 준비

- **C-B** (`crates/tidydog-core/src/content.rs`): `ContentReader` 트레이트, `ContentBudget { max_chars:4096, max_pages:Some(5) }`, `ContentChunk`, `ReaderError` — 외부 의존성 0 유지.
- **C-C** (`crates/tidydog-core/src/summary.rs`): `Summarizer` 트레이트, `SummaryHints`, `SummaryResult`, `SummaryError` — 외부 의존성 0 유지.
- `crates/tidydog-core/src/lib.rs`에 두 모듈 pub 추가.
- **T1 준비** (`src-tauri/src/db.rs`): `plan_ops` 테이블(op_id, plan_id, seq, action, content_hash, from_path, to_path, conflict, reason) + `settings` 테이블 + `summaries` 테이블 스키마 추가.

#### SA1 — Python 사이드카 (`sidecar/reader.py`, 205줄)

- **프로토콜 C-A**: stdin `{"path":"...","max_chars":N}` → stdout `{"text":"...","pages":N,"truncated":bool,"error":null}`.
- txt/md/rst: UTF-8 읽기, latin-1 fallback. pdf: pypdf 우선, pdfplumber fallback.
- budget: `max_chars`에서 잘라내기, `pages_read` 보고.
- N5: 파일 쓰기·이동·삭제 호출 없음. 에러는 모두 `{"text":"","error":"..."}`로 exit 0 반환.
- `sidecar/requirements.txt`: `pypdf`.

#### SA2 — SidecarReader Rust 어댑터 (`src-tauri/src/reader.rs`, 200줄)

- `SidecarReader { python_bin: String, script_path: PathBuf }` → `ContentReader` 구현.
- `std::process::Command` stdin/stdout 파이프; async 미사용.
- sidecar `error` 필드 → `ReaderError::ParseFailed`로 매핑.
- 테스트 4개: `n3_budget_enforced_large_file`, `n3_small_file_not_truncated`, `broken_pdf_returns_err_not_content_chunk`, `missing_file_returns_err`. python3 또는 sidecar/reader.py 없으면 자동 스킵.

#### SA3 — CloudSummarizer (`src-tauri/src/summarizer.rs`, 336줄)

- `CloudSummarizer<'a> { conn: &'a Connection }` → `Summarizer` 구현.
- `is_consented()`: `settings WHERE key='ai_content_consent_granted'` → value `'true'`이면 true; 행 없거나 `'false'`이면 false.
- `summarize()` 실행 순서: (1) 동의 체크 → (2) content_hash 캐시 조회(summaries 테이블) → (3) keyring 조회(`keyring::Entry::new("tidydog","anthropic_api_key")`) → (4) Claude API 호출(POST `https://api.anthropic.com/v1/messages`, model `claude-haiku-4-5-20251001`, max_tokens 256) → (5) 캐시 저장.
- 에러 매핑: 429 → `RateLimited`, JSON 파싱 실패 → `ParseError`, 기타 → `ApiError`.
- `in_memory_for_test()` 생성자로 단위 테스트 격리.
- `src-tauri/Cargo.toml`에 `reqwest = { version = "0.12", features = ["blocking", "json"] }`, `keyring = "3"` 추가.
- 테스트 5개: `n1_no_consent_row_returns_not_consented`, `n1_consent_false_returns_not_consented`, `is_consented_true_when_setting_true`, `cache_hit_returns_stored_result_no_api_call`, `cache_miss_with_consent_fails_at_keychain_not_at_consent_gate`.

#### SA4 — 규칙 파서 + 위키 렌더러

**`src-tauri/src/organizer.rs` (246줄)**

- 테스트 6개: `test_derive_dest_basic`, `test_parse_skips_comments_and_blank`, `test_multi_clause_and_logic`, `test_name_clause`, `test_first_match_wins`, `test_tag_case_insensitive`.

**`src-tauri/src/wiki.rs` (414줄)**

- `write_log(root, conn)` → `log.md` (journal 최근 200건).
- 테스트 5개: `test_write_file_wiki_page`, `test_write_file_wiki_page_no_optionals`, `test_parse_tags_json`, `test_unix_secs_to_iso`, `test_write_index_and_log_empty_db`.

#### 안전 감사 — N1 게이트 위치 결함 발견 및 수정

- **발견 경위**: "N1 동의 게이트가 (a) 파일 내용 읽기 전인가, (b) 읽은 후 전송 직전인가?" 점검 질문. `lib.rs`의 `index_file_content` 흐름을 추적하니 `SidecarReader::read_content()` 호출 → `CloudSummarizer::summarize()` 순서였고, `is_consented()` 체크는 `summarize()` 안에만 있었다.
- **결함**: 미동의 상태에서 Python 사이드카가 실행되고 파일 내용이 `ContentChunk` (Rust 힙)에 올라온 후에야 `NotConsented`가 반환됐다.
- **수정** (`src-tauri/src/lib.rs`, N1 gate 삽입):
  ```
  db::init_db() 직후, SidecarReader 생성 전
  → CloudSummarizer::new(&conn).is_consented() 체크
  → false이면 즉시 Err 반환
  ```
  `summarize()` 내부 체크는 방어적 이중 확인으로 유지.
- `summarize()` 안의 `is_consented()` 체크가 이후 항상 통과됨을 `cache_miss_with_consent_fails_at_keychain_not_at_consent_gate` 테스트로 확인 (실패 지점이 keychain/API이고 NotConsented가 아님).

#### T2 — 스펙 역반영

- **`docs/데이터모델.md` (신규)**: files·plans·plan_ops·journal·staging·summaries·settings 테이블 전체 문서화. `journal.completed_at` 의미(intent/complete 구분), plan_ops dual-write 현황, staging = 앱 관리 디렉터리(OS 휴지통 아님), P3 컬럼 채워지는 시점.
- **`docs/안전명세.md` (신규)**: S1–S6 코드 경로, N1–N5 테스트 목록, 미구현 항목 표. "삭제=staging" 의미 명확화, journal-first + op단위 내구성 + recover_inflight 섹션 추가.

## 미해결·추적 항목

1. **T1 plan_ops 정규화 잔여**: dual-write 구현됐으나 기존 플랜의 `ops_json` → `plan_ops` 마이그레이션 배치 스크립트 없음. 현재는 새 플랜만 plan_ops에 들어감.
2. **staging 30일 purge (P5)**: `staging.purge_after` 컬럼 예약됨. 실제 퍼지 로직 없음. 현재 staging 파일은 수동 정리 필요.
3. **사이드카 프로덕션 번들링**: `index_file_content`가 `std::env::current_dir().join("sidecar/reader.py")`를 사용. 프로덕션 CWD는 예측 불가. 앱 번들에 사이드카 포함하는 Tauri 플러그인·사이드카 메커니즘 미구현.
4. **`read_level='content'` N4 스코프 가드**: `index_file_content` 성공 후에만 업그레이드하는 코드는 있으나, "content 파일만 내용을 읽는다" 방향 — 재스캔 시 metadata 파일의 `index_file_content` 호출을 프론트엔드가 막아야 하는 책임이 명시되지 않음.
5. **wiki 자동 트리거**: `rebuild_wiki` 커맨드는 수동 호출. 파일 인덱싱 후 자동 갱신 연결 미구현.
6. **`trash` 크레이트 의존성 잔류**: `Cargo.toml`에 남아 있으나 현재 코드에서 미사용. 정리 필요.
