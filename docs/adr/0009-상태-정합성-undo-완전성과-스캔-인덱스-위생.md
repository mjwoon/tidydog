# ADR-0009 — 상태 정합성: undo 완전성 + 스캔 인덱스 위생

| 항목 | 내용 |
|------|------|
| **상태** | 수용됨 (2026-07 신뢰성 세션) |
| **결정자** | 프로젝트 오너 |
| **관련** | ADR-0002(journal-first), ADR-0003(staging) |

---

## Context

두 개의 독립된 "지속 상태가 현실과 어긋나는" 결함이 실사용 검증에서 드러났다. 둘 다
"파일 이동 자체는 맞는데, 그 주변 상태가 실제 FS를 정확히 반영하지 못한다"는 공통 성격이다.

**결함 A — undo가 생성 폴더를 남긴다.**
`execute`의 `move_file`은 `create_dir_all`로 목적지 폴더 트리를 만든다. `undo`는 파일을
원위치로 되돌리지만, 그때 생긴 빈 폴더는 저널에 기록이 없어 지우지 못한다. undo가 완전한
역연산이 아니었다(파일은 복원되나 폴더 잔재가 남음).

**결함 B — 스캔 인덱스가 유령을 남긴다.**
`scan_directory`/`tool_scan`은 `files` 테이블을 `current_path` 기준 UPSERT만 하고, 사라진
파일의 행을 지우지 않았다. 조직→undo 반복 후 stale 인덱스가 누적되어, 같은 `content_hash`가
현재 경로 + 유령 경로 두 벌로 잡혔다. 에이전트가 존재하지 않는 "중복본"을 탐지해 모순된
플랜(파일 10개에 이동 10 + 중복격리 7 = 17-op)을 냈다.

---

## Decision

**지속 상태(저널·스캔 인덱스)가 execute 이후 실제 FS를 정확히 반영하도록, 되돌림과
스캔에 정리 단계를 추가한다. 파괴적 삭제는 하지 않는다.**

**A. undo가 생성 폴더를 제거한다.**
- `execute`가 move 목적지에서 **새로 만든 상위 디렉터리**를 계산해 저널 엔트리에 기록
  (`JournalEntry.created_dirs`, 깊은 것부터). 이미 있던 폴더는 포함하지 않는다.
- `undo`는 파일 복원 후 `created_dirs`를 깊은 것부터 `remove_empty_dir`로 제거한다.
  `std::fs::remove_dir`는 **빈 폴더만** 지우고 비어 있지 않으면 Err → 무시(보존). 재귀 삭제
  없음, 사용자가 미리 만든 폴더는 제거하지 않는다.
- `created_dirs`는 **저널/store 레이어 확장**이다. op 스키마 계약(op_id/action/from/to/…)은
  불변으로 유지한다.

**B. 스캔이 사라진 인덱스를 prune한다(mark-sweep).**
- `scanner::scan_and_prune`: 스캔 시작 시각을 잡고, 스캔 후 `last_seen`이 그보다 오래된
  (= 이번 스캔에서 못 본) root 하위 행을 삭제한다.
- 현재 존재하는 파일은 재스캔에서 `last_seen`이 갱신되어 보존(summary·proposed_dest 캐시 포함).
- FE `scan_directory`와 **에이전트 `tool_scan`이 이 헬퍼를 공유** — 에이전트가 보는
  데이터에서 유령을 제거하는 것이 핵심(FE 트리만 고쳐서는 불충분).

---

## Consequences

**긍정**

- undo가 execute의 완전한 역연산이 된다(파일 + 폴더 원복).
- 스캔 인덱스가 실제 FS와 일치해 유령 중복본 오판이 사라진다.
- 어느 쪽도 파괴적이지 않다: `remove_empty_dir`는 빈 폴더만, prune는 사라진 인덱스 행만 지운다.

**비용**

- `created_dirs` 컬럼 추가로 journal 스키마 마이그레이션이 필요(기존 DB `ALTER TABLE`, 기본 `[]`).
- 마이그레이션 이전에 실행된 플랜은 `created_dirs`가 비어 있어 undo가 그 폴더를 못 지운다
  (소급 불가 — 새 플랜부터 적용).
- mark-sweep은 초 단위 `last_seen` 비교라, 같은 초에 연속된 두 스캔에서 사라진 항목은 다음
  스캔까지 한 번 늦게 제거될 수 있다(정확성 문제 아님, 현재 파일은 절대 오삭제 안 됨).
