# ADR-0008 — LLM 출력 렌더 안전 (마크다운, raw HTML·위험 스킴 차단)

| 항목 | 내용 |
|------|------|
| **상태** | 수용됨 (Phase 4 챗 UI, 2026-07) |
| **결정자** | 프로젝트 오너 |

---

## Context

Phase 4 챗 UI는 에이전트(Claude) 응답을 챗 버블에 렌더한다. 에이전트 응답은 구조적
마크다운(제목·목록·코드블록)이라 평문(`whiteSpace: pre-wrap`)보다 마크다운 렌더가 가독성이
높다.

그러나 **LLM 출력은 신뢰할 수 없는 입력**이다. 프롬프트 인젝션이나 모델 환각으로 응답에
`<script>`, `<img onerror=...>`, `javascript:`·`data:` 링크 같은 위험 콘텐츠가 섞일 수 있다.
마크다운 렌더러가 raw HTML을 통과시키거나 위험 스킴 링크를 활성 링크로 만들면 데스크톱
웹뷰 안에서 코드 실행/피싱 표면이 생긴다.

---

## Decision

**에이전트 메시지만 마크다운으로 렌더하되, raw HTML을 렌더하지 않고 링크 스킴을
화이트리스트(http/https)로 제한한다. 사용자·에러 메시지는 평문으로 둔다.**

- 렌더러: `react-markdown` + `remark-gfm`. **`rehype-raw`·`dangerouslySetInnerHTML`을
  도입하지 않는다** — react-markdown 기본값이 문자열 내 HTML을 파싱하지 않고 텍스트로 처리한다.
- 링크 스킴 이중 방어:
  1. react-markdown 기본 `urlTransform`이 `javascript:`·`data:` 등을 무력화.
  2. 커스텀 `a` 컴포넌트가 `^https?://` 아닌 href를 **클릭 불가한 평문(span)** 으로 렌더.
- 파싱 범위: **assistant(비-에러) 메시지에만.** 사용자 입력·에러 메시지는 평문 유지
  (`isUser || isError`이면 `pre-wrap`, 아니면 마크다운).
- 디자인 토큰만 사용(빨강 금지, 모노=IBM Plex Mono). 새 폰트·색 도입 없음.

---

## Consequences

**긍정**

- LLM이 무엇을 출력하든 스크립트 실행·raw HTML 주입이 불가능하다(파서가 텍스트로 처리).
- 위험 스킴 링크는 클릭 불가 평문으로 떨어져 피싱 클릭 표면이 없다.
- 사용자가 입력한 텍스트는 마크다운 파싱을 거치지 않아, 사용자 입력이 렌더 로직을 흔들 수 없다.

**비용**

- 에이전트가 의도적으로 HTML/iframe 임베드를 원해도 불가(정책상 허용 안 함).
- 마크다운 파싱 비용이 메시지마다 든다(경미).

**관련 코드 경로**

- `src/components/MarkdownMessage.tsx` — react-markdown 설정, `isSafeHref`, 커스텀 컴포넌트.
- `src/components/Chat.tsx` — assistant(비-에러)만 `<MarkdownMessage>`, 그 외 평문.
- `src/styles.css` — `.md-body` 마진 정리.
- CLAUDE.md "LLM 출력 렌더 안전" 절 — 이 ADR의 요약 규칙.
