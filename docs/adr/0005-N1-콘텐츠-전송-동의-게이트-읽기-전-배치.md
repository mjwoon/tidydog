# ADR-0005 — 콘텐츠 클라우드 전송 동의 게이트를 "읽기 전"에 배치 (N1)

| 항목 | 내용 |
|------|------|
| **상태** | 수용됨 (Phase 3 안전 감사 후 수정, 2026-06-29) |
| **결정자** | 프로젝트 오너 (감사 후 수정 지시) |

---

## Context

### 최초 구현의 게이트 위치

Phase 3 SA3(CloudSummarizer) 초기 구현에서 동의 체크는 `summarize()` 메서드 내부에 있었다.

```rust
// 초기 구현 — summarize() 안
fn summarize(&self, chunk: &ContentChunk, hints: SummaryHints) -> Result<...> {
    if !self.is_consented() {           // ← 동의 체크
        return Err(SummaryError::NotConsented);
    }
    // ... API 호출
}
```

`summarize()`를 호출하는 `index_file_content` 커맨드는 다음 순서로 실행됐다.

```
1. SidecarReader::read_content()  ← 파일 내용을 메모리에 적재
2. CloudSummarizer::summarize()   ← 여기서 동의 체크 (너무 늦음)
```

### 발견된 문제

파일 내용이 이미 `ContentChunk`(Rust 힙 메모리)에 올라간 뒤에야 동의를 확인한다.

이는 N1 요구사항의 위반이다:

> N1: 사용자 동의 없이 파일 내용을 클라우드로 보내지 않는다.  
> **동의 게이트는 전송 경로 진입 전(내용 읽기 전)이어야 한다.**

"클라우드로 전송"뿐 아니라 "파일 내용을 읽는 것"(사이드카 프로세스 실행 포함)이 동의 범위에 포함된다. 미동의 상태에서:
- Python 사이드카 프로세스가 실행됐다.
- 파일 내용이 메모리에 올라왔다.
- 이후에야 `NotConsented` 에러가 반환됐다.

이 감사는 코드를 실제로 추적한 결과로 발견됐으며, 문서 상으로는 "summarize() 안에 게이트 있음"으로 기록되어 있어 언뜻 보면 문제가 없어 보였다.

---

## Decision

**동의 게이트를 `index_file_content` 커맨드 진입 직후, 사이드카 실행 이전으로 이동한다.**

```rust
// 수정 후 (src-tauri/src/lib.rs)
fn index_file_content(...) {
    let conn = db::init_db(&app_data_dir)?;

    // N1: 동의 게이트 — 파일 내용을 읽기 전에 확인.
    // 미동의 시 사이드카 프로세스 미실행 + 네트워크 호출 0.
    if !CloudSummarizer::new(&conn).is_consented() {
        return Err("user has not consented (N1)");
    }

    // 이 줄 이후에만 사이드카 실행 허용
    let reader = SidecarReader::new("python3", script_path);
    let chunk = reader.read_content(...)?;  // ← 동의 확인 후
    ...
    summarizer.summarize(&chunk, hints)?;   // 내부에도 is_consented() 재확인 (방어적)
}
```

`summarize()` 내부의 체크는 방어적 이중 확인으로 유지한다. 단일 진입 경로 보장을 위한 것이며, 주 게이트는 커맨드 레벨이다.

동의 상태는 `settings` 테이블의 `ai_content_consent_granted` 키로 관리한다. 행이 없거나 값이 `'false'`이면 미동의로 간주한다.

---

## Consequences

**긍정**

- 미동의 시 파일 내용이 전송 경로에 진입하지 않는다. 사이드카 프로세스 자체가 실행되지 않는다.
- 이 동작이 테스트로 고정된다 (아래 참조).
- "파일 내용을 읽는 것 = 전송 경로 진입"이라는 보다 엄격한 해석을 구현에 반영한다.

**비용**

- `index_file_content`가 `CloudSummarizer`를 동의 확인 목적으로 먼저 생성해야 한다 (DB 연결 비용은 이미 발생 중).
- `summarize()` 안의 동의 체크가 "항상 통과"하는 중복 체크가 된다 (방어적 코딩, 미래 호출 경로 추가 시 안전망).

**테스트로 양방향 고정**

게이트 동작이 다음 두 방향에서 모두 검증된다.

1. **미동의 → NotConsented 반환**  
   - `src-tauri/src/summarizer.rs::tests::n1_no_consent_row_returns_not_consented`  
     settings 행 없음 → `SummaryError::NotConsented` (API/keychain 미도달 증명)
   - `src-tauri/src/summarizer.rs::tests::n1_consent_false_returns_not_consented`  
     value=`'false'` → `SummaryError::NotConsented`

2. **동의 후 캐시 히트 → API 미호출 성공**  
   - `src-tauri/src/summarizer.rs::tests::cache_hit_returns_stored_result_no_api_call`  
     동의 true + 캐시 선점 → keychain/네트워크 없이 `Ok(SummaryResult)` 반환  
     (테스트 환경에 API 키 없으므로, 캐시를 거치지 않으면 이 테스트가 실패한다)

3. **동의 후 캐시 미스 → 실패 지점이 keychain/API, NotConsented 아님**  
   - `src-tauri/src/summarizer.rs::tests::cache_miss_with_consent_fails_at_keychain_not_at_consent_gate`

**관련 코드 경로**

- `src-tauri/src/lib.rs::index_file_content` (245~265행) — 게이트 위치
- `src-tauri/src/summarizer.rs::CloudSummarizer::is_consented` — settings 테이블 조회
- `src-tauri/src/summarizer.rs::CloudSummarizer::summarize` (178~180행) — 방어적 이중 체크
- `crates/tidydog-core/src/summary.rs::Summarizer` 트레이트 — `is_consented()` 시그니처 명세
